# 符号与力矩正方向校核：法向力向下、垂直力向上，取矩前先声明往哪边转

## R — 原文 (Reading)

> **原书要点**（p34 §1.3.6）：按这套约定，沿 x 轴正向的纵向力代表车往前走；而地面顶住轮胎的那个支撑力指向上方，在 z 轴里就算负值。SAE 的 J670e 标准（即《车辆动力学术语》）为了便于记，把朝下的唤作"法向力"、朝上的唤作"垂直力"（参见附录 A），所以与支撑力同向的这种力取正号。别国并不都这么定。
>
> **原书要点**（p36 §1.4；p39 例题3）：在 SAE 这套约定里，绕 A 点按顺时针转的力矩记作正；换成取轮胎与路面接触点作矩心时，则改为逆时针为正，据此列力矩平衡式。
>
> — 1.3.6 作用力（p34）；1.4（p36）；1.5 例题 3（p39）

## I — 方法论骨架 (Interpretation)

一句话：**同一章里有两套"看起来都对"的符号约定叠在一起——轴的朝向与力的命名、以及力矩的正方向——所以每次列式前必须把三件事写成一行：z 朝哪、力叫什么、绕哪点往哪边转为正。**

- **第一层：轴与命名。** SAE 车辆固定坐标系 z 轴**向下**，于是重力在 $+z$；但轮胎支撑力向上，是 $z$ 的反方向。为了口头上不混乱，SAE J670e 把"向下的力"命名为**法向力**、"向上的力"命名为**垂直力**，并规定垂直力向上为正。结果：车轴载荷 $W_f$、$W_r$ 属于**垂直力、取正值**。这与中文文献里"法向力 = 支撑力"的习惯正好相反——原文还专门补了一句"在其他国家，这些规则会有所不同"。
- 判别法只有一条：**看箭头，不看词。** 向下 → 法向力；向上 → 垂直力。
- **第二层：力矩正方向。** 1.4 节对后轮接地点 A 取矩求前轴载荷，声明"顺时针为正"；例题 3 对轮胎接地点取矩，声明"逆时针为正"。两者相反，且**各自都明说了**——这说明作者知道读者会带着上一节的约定过来。
- 正方向本身无害：换了方向只让整式乘 $-1$。**危险在混合**：只要方程里有一项按另一套约定写，就等于给那一项偷偷加了负号，方程不再自洽，表现为两轴载荷互换、解出负值、拖钩力方向反。
- **第三层：轴角速度按轴不按字母。** 1.3.2 的正文在 OCR 里把侧倾角速度印成"绕 r 轴"，并丢失了 z 轴与横摆 $r$ 的整句。正确关系是：绕 x = 侧倾（$p$）、绕 y = 俯仰（$q$）、绕 z = 横摆（$r$）。**引用时以"绕哪根轴"为准，不以字母为准**——因为字母被印错过一次，公式仍然"读得通"，只是侧倾与横摆整个换了位置。
- 这三层合起来的作用是**在计算之前把符号钉死**：符号错是本章唯一"数值看起来差不多、但链条全反"的错误类型，而且它不会被求和自检以外的任何检查发现。

## A1 — 应用示例 (Application Example)

### 示例 1：本章两处相反的力矩约定（原文对照）

- **类型与来源**：**原书原文对照**（1.4 p36；例题 3 p39）。这不是例题，而是同一章内两处各自声明的约定。
- **1.4 节**：对后轮接地点 A 取矩求 $W_f$，**顺时针为正**；式 (1-3) 写成 $W_fL+D_Ah_a+\tfrac{W}{g}a_xh+R_{hx}h_h+R_{hz}d_h+Wh\sin\theta-Wc\cos\theta=0$（按原图公式块重建，正文尾部残缺，H6）。
- **例题 3**：对轮胎接地点取矩，**逆时针为正**；式 (3) 写成 $\Sigma T_y=0=Wh_1\sin\theta-Wc\cos\theta+F_{zb}d+F_{xb}h_2+W_f(b+c)$。
- **可判定的后果**：把例题 3 的整式换成顺时针约定，每项符号全反、与原文差整体 $-1$，两边等价（无害）；但若只改 $W_f(b+c)$ 一项而其余不动，$W_f$ 的系数变号，解出的两个轴荷**互换**——这正是"混用"的可观测症状。

### 示例 2：跨标准符号对接（合成演练，非书中事实）

- **类型与来源**：**合成演练**。原书未给跨标准例题；此处用一条构造输入验证"看箭头不看词"这条判据。
- **输入**：一份 ISO 系资料给出某车轮 "normal force = 4000 N（竖直向上支撑车身）"，要代入本书的轴荷式。
- **方法的执行**：看箭头——向上 → 按 SAE 命名它是**垂直力** → 与本书 $W_f$ 同向 → 取 $+4000$ N（换算成 lb 后）作 $W_f$ 的正值。若对方 normal force 指向下（SAE 义的真正法向力，例如车轮对地面的压力），则与本书 $W_f$ 反号。
- **结论/预期输出**：$W_f=+4000$ N 折算值；**反号复核**——若取错号，$W_f+W_r$ 会变成 $-W\cos\theta$ 或出现负的轴荷，两个条件同时破。

### 示例 3：轴角速度的按轴复核（合成演练，非书中事实）

- **类型与来源**：**合成演练**。原书该段 OCR 残缺（H4），此处只演示"按轴不按字母"的复核动作，不补造原文。
- **输入**：一段抄来的文字"侧倾角速度为绕 r 轴"。
- **方法的执行**：查轴——侧倾是绕 **x** 轴，故侧倾角速度是 $p$；横摆是绕 **z** 轴，故是 $r$。
- **结论/预期输出**：判该句为 OCR/排版错，按 $p$（侧倾，绕 x）、$q$（俯仰，绕 y）、$r$（横摆，绕 z）复原；引用时写"绕 x 轴"而不写字母，避免二次传播。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个方法？

1. 从外文/他国标准/别的软件里搬来一套力与力矩，要接进本书（或 SAE 体系）的式子。
2. 算出的轴荷出现负值、或上坡时前轴载荷变大、或 $W_f+W_r=-W$——要定位是不是符号反了。
3. 一段推导里找不到力矩正方向声明，或前两节用顺时针、后一节用逆时针。
4. 看到"法向力""垂直力"两个词并用，想确认哪个是支撑力。
5. 代码/文档里 $p$、$q$、$r$ 与实际绕轴对不上，怀疑被 OCR 或翻译串过。

### 语言信号（中英双写）

- 「法向力和垂直力有什么区别」「轮胎支撑力该取正还是负」「z 轴朝下还是朝上」
- 「力矩正方向怎么定」「顺时针还是逆时针为正」「为什么算出来轴荷是负的」
- 「normal force vs vertical force」「sign convention」「SAE J670e」「roll rate p yaw rate r」

### 与相邻能力的区分（初稿，阶段 3 定稿）

## E — 可执行步骤 (Execution)

**必需输入**：待接的符号/公式来源（书名或标准号 + 该处的正方向声明）、待代入的目标式（本章哪一条）、力的箭头方向（或"向上/向下支撑"的文字描述）。

**缺什么必须问**：来源未声明 z 轴指向 → 停（z 向上与向下的整套符号相反）；来源未声明力矩正方向 → 停（不可默认与本章一致）；"normal force"未说明箭头方向 → 停（同名反义，猜必错）。

**交付物与完成标准**：一张四行校核表（轴 / 力命名 / 力矩 / 角速度）+ 一句"已声明"结论 + 若有换算则附换算后的数值。

1. **钉 z 轴（第一行）**
   - 完成标准：写出"本章 z **向下**、原点在重心、随车运动；重力在 $+z$"。来源若 z 向上，全表逐项反号后再用。
2. **钉力命名（第二行）**
   - 完成标准：写出"向下 = 法向力；向上 = 垂直力；$W_f$、$W_r$ 属垂直力、**取正**"。然后对每一个待接的力做"看箭头"判定，写"向上 → 与 $W_f$ 同向 → 取 +"。
   - 判停：若某来源把轮胎支撑力叫"法向力"（几何义），**不得**因此把它取负——按箭头判，不按词判。
3. **钉力矩正方向（第三行）**
   - 完成标准：每个取矩式前单独声明"对 X 点取矩，顺时针/逆时针为正"，并回显该声明；同一段推导内只允许一套。
   - 判停：若前文用顺时针、此处用逆时针，**整式乘 $-1$ 重写**，不许只改部分项；改完用"$W_f>0$、$W_r>0$、$W_f+W_r=W\cos\theta+R_{hz}$"三条验一次。
4. **钉角速度按轴（第四行）**
   - 完成标准：写"绕 x = 侧倾 $p$；绕 y = 俯仰 $q$；绕 z = 横摆 $r$"，并在引用处写"绕 x 轴"而非只写字母。
5. **交付**
   - 完成标准：一句话"已按 SAE J670e 校核：z 向下、支撑力为垂直力取正、本例对后轮接地点顺时针为正、p/q/r 按 x/y/z"；若做过换算，附换算前后数值与"整式乘 $-1$ 等价"的说明。

**计算约定（本卡设定）**：符号核查表固定四行（轴 / 力命名 / 力矩 / 角速度），缺行即未完成；"整式乘 $-1$ 等价、部分项改号即错"作为唯一判据。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此方法

- **按字面"垂直=向上"想当然。** 中文文献里"法向力"几乎总指支撑力（向上），与 SAE 命名正好相反；跨资料检索时这是最常见的串味点（ce04）。
- **据 1.4 第 (3) 条的"沿路面法向方向"去改方向。** 那里的"法向"是**几何**意义（垂直于路面），与 SAE 命名的"法向力（向下）"含义相反；两处并存，按上下文区分，$W_f$、$W_r$ 仍取正。
- **在同一段推导里混用两套力矩正方向。** 只改部分项会让两轴载荷互换、出现负值、拖钩力反向；整式乘 $-1$ 才无害（ce09）。
- **把 $p$、$q$、$r$ 按字母认轴。** OCR 已把侧倾角速度印成"绕 r 轴"一次（H4）；以"绕哪根轴"为准。
- **只在开头声明一次就贯穿全章。** 本章两节约定相反，是作者刻意各自声明的；跨节复用必须重新声明。
- **把它当"更精确"的检查。** 本卡只保证符号一致，不保证数值正确；数值仍要过求和自检。
- **在未声明 z 轴指向的资料上直接套本章式子。** z 向上的体系里，重力、轮荷、垂向加速度、侧倾力矩的符号会连锁错到底。

### 作者在书中警告的失败模式

- ce04（明确警告）：符号搞反——作者特意写"在其他国家，这些规则会有所不同"，正是针对跨资料抄符号。
- ce09（定义型，两处各自明说且相反）：力矩正方向混用；本章两处约定相反这一事实本身就是警告。
- ce03（明确警告）：欧拉角次序不可换——同一族的"约定即定义"错误，姿态矩阵换序等于换了定义。
- ce13（定义型）：上坡 $\theta$ 正、下坡 $\theta$ 负——输入符号层，与本卡的约定层会互相掩盖。

### 作者的盲点 / 时代局限

- 本章没有给出完整的 SAE J670e 符号表（只有"见附录 A"），p/q/r 与 z 轴的定义句还在 OCR 中残缺（H4）；欧拉角的三个角符号、旋转矩阵、转角正负号原文均未给。
- 只列了"法向力/垂直力"这一组命名，未系统给出轮胎力、气动力、拖钩力的正方向表。
- 附录 A 未纳入本次蒸馏范围，跨标准核对只能做到"按箭头判"，无法给出逐符号对照表。

### 容易混淆的邻近方法论

- **法向力（向下）vs 垂直力（向上）**：同名反义，唯一判据是箭头。
- **"几何法向"（垂直路面）vs "命名法向"（向下）**：1.4(3) 与 1.3.6 用的是两个不同意义的"法向"。
- **整式乘 $-1$（等价）vs 部分项改号（错）**：换约定必须整式重写。
- **角位移（$\phi$、$\theta$、$\psi$）vs 角速度（$p$、$q$、$r$）**：本章 1.3.2 只定义了角速度，三个角位移符号在正文中根本没印出来。
